# The STACKFALL soundtrack

Twelve tracks in three collections of four, generated by code. The catalogue
builds once per session from fixed pattern data in `src/music_tracks.cpp`
through the `Arranger` composer; no audio file is read or shipped. The
engine (`src/music.cpp`, `include/stackfall/music.hpp`) renders the same
note data at any sample rate; the director (`src/music_director.cpp`) maps
scenes, the level, and the player's settings onto it. See `MUSIC.md` for
the plan this implements and section 6.4 of `docs/SPEC.md` for the
specification view.

## Workflow choice

MUSIC.md allows Strudel sketches beside the native engine. This catalogue
skipped them: the composer is native C++ from the start, so what the
previews render is exactly what the device plays. There is no
sketch-to-engine difference to document because no sketch exists; the
arrangement contract and the note tables in `src/music_tracks.cpp` are the
source of truth, and the records here describe them.

## Render evidence

`build/stackfall_music_preview --intensity all --out build/music-previews`
renders all 36 combinations (12 tracks, 3 intensity maps) at 44100 Hz. The
full run of 2026-11-04 reports zero clipped samples, DC offsets within 61 of
32768, and a voice ceiling of 12 (the budget), with the loudest peak at
28955 of 32767. The report line per file sits in
`build/music-previews/report.txt`.

## Listening status

All twelve records carry listening status **pending**: the machine checks
cover validation, timing, levels, and the loop seam, and the human pass on
headphones and handheld speakers remains open (MUSIC.md, listening checks).
